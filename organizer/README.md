# Организаторская сборка

Здесь лежит полная версия среды и оценщик, которым считается результат присланной
модели. Студенческая сборка отличается составом банка: тестовых биомов в ней нет.

## Сборка

```bash
cd organizer
make build
```

Ставит два пакета в editable-режиме — саму среду и оценщик — и добавляет команду
`mars-rover-score`.

## Оценка модели

```bash
mars-rover-score /путь/к/model.zip
```

То же через Makefile:

```bash
make score MODEL=/путь/к/model.zip
make score MODEL=/путь/к/model.zip ARGS="--device cuda --output run1.json"
```

| аргумент | по умолчанию | назначение |
|---|---|---|
| `model` | обязательный | чекпоинт SB3 PPO (`.zip`) |
| `--output` | `score.json` | куда писать полный отчёт |
| `--device` | `cpu` | можно `cuda` |

Модель должна использовать не больше 27 действий — столько макросов в наборе
организатора. Если действий больше, оценщик откажется стартовать с явной
ошибкой, а не молча посчитает ерунду.

## Из чего состоит прогон

45 заездов по 300 секунд, все считаются одним пакетом параллельно:

- **8 биомных сценариев** — по одному фиксированному тестовому биому на каждый:
  `speed_band_talus`, `cadence_dune_belt`, `geyser_basin`, `fall_line_ridges`,
  `sink_moon_bog`, `tide_swing_basin`, `hardpan_rebound`, `blind_traction_flats`;
- **7 цепочечных сценариев** — трасса собирается из тестового сплита по seed.

`gale_dark_flats` и `battery_bay_tycho` в банке остались, но отдельных сценариев
у них нет: зарядиться внутри них нельзя, поэтому соло они меряют не езду, а
ёмкость батареи. В цепочках они по-прежнему выпадают — там перед ними и после
них есть где восполнить заряд.

Каждый сценарий прогоняется **на трёх сидах подряд**: `seed`, `seed + 1`,
`seed + 2`. Это три разных мира одного и того же типа, чтобы результат не
зависел от одной удачной или неудачной трассы.

Все заезды идут с `force_endgame_difficulty`, то есть на максимальной сложности
рельефа с первого метра.

## Сиды

Пятнадцать базовых сидов лежат в `evaluator/.env` одной строкой через запятую:

```
MARS_ROVER_TEST_SEEDS=97308804,54984754,...,104110937
```

Порядок важен: первые восемь чисел отвечают биомным сценариям в порядке
каталога (без двух цепочечных биомов), последние семь — цепочечным. Значения принимаются десятичные и
шестнадцатеричные (`0x...`), пробелы вокруг запятых допускаются, строки с `#`
игнорируются.

Оценщик проверяет, что сидов ровно 15, и падает с понятной ошибкой, если их
меньше, больше или среди них мусор. Другой файл можно подставить переменной
окружения `MARS_ROVER_TEST_SEEDS_FILE`.

Менять сиды между прогонами разных моделей нельзя: сравнение станет
бессмысленным. Меняете — перегоняйте всех заново.

## Что на выходе

В консоль печатается сводка:

```json
{
  "score": 128.4,
  "biome_mean": 141.2,
  "chain_mean": 102.9,
  "episodes": 45,
  "wall_seconds": 63.1,
  "realtime_speedup": 213.9
}
```

`score` — средняя пройденная дистанция в метрах по всем 45 заездам.
`biome_mean` считается по 24 биомным прогонам, `chain_mean` — по 21 цепочечному.

В `score.json` дополнительно лежит построчный разбор:

```json
{
  "scenario": "biome:geyser_basin",
  "seed": 452786628,
  "base_seed": 452786626,
  "replica": 2,
  "distance": 96.4
}
```

По `base_seed` и `replica` видно, какие строки относятся к одному сценарию, то
есть можно посмотреть разброс между тремя мирами, а не только среднее.

## Если что-то пошло не так

- **`test seed file does not exist`** — нет `evaluator/.env` или сбит путь в
  `MARS_ROVER_TEST_SEEDS_FILE`.
- **`must contain exactly 15 test seeds`** — в списке не 15 чисел.
- **`organizer build must contain exactly 10 test biomes`** — собрана не та
  версия банка; пересоберите `make build` в этом каталоге, а не в `student`.
- **`model has N actions`** — модель обучена на другом наборе действий.
