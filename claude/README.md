# RL² для Mars Rover

## Что за задача на самом деле

Разбор среды (`environment/cpp/src/env.cpp`, `include/mars/env.hpp`):

* `Env::reset(seed, trial_start)` фиксирует `trial_mechanic_seed_` только при
  `trial_start`. Внутри трайла (`episodes_per_trial = 4`) биом, цепочка зон
  (`chain_zone_count = 14`), механики (Sand/Ice/Mud/Wind/LowGravity/Crust/Liquid)
  и сид рельефа **не меняются**. Между трайлами — меняются полностью.
* Механики влияют на трение, вязкость, ветер, гравитацию, температуру,
  расход/заряд энергии, дальность лидара — их **нельзя наблюдать напрямую**.
* Рельеф виден только при активном лидаре (`obs` зануляется, когда лидар выключен),
  а лидар стоит энергии и имеет кулдаун.

То есть это не «одна среда, которую перегенерируют», а **распределение задач со
скрытой переменной**, постоянной внутри трайла. Обычный PPO с MLP тут может
выучить только усреднённую по всем биомам политику.

## Решение: RL² (recurrent meta-RL)

Политика — GRU, скрытое состояние **переносится через границы эпизодов внутри
трайла** и обнуляется только на `trial_start`. Наблюдение расширено историей:
`[obs, one-hot(prev_action), prev_reward, done, one-hot(episode_in_trial)]`.

Так PPO оптимизирует награду за трайл целиком, и градиент сам выучивает:
* эпизод 1 — разведка (включить лидар, попробовать газ, понять сцепление/ветер);
* эпизоды 2–4 — эксплуатация выведенного «типа мира» (передачи, момент тормоза,
  когда заряжаться, когда тратить энергию на лидар).

Никакого явного оценщика биома: скрытое состояние GRU играет роль belief-state,
адаптация происходит forward pass'ом, без градиентных шагов на тесте (в отличие
от MAML) — это и есть «как можно быстрее адаптируется».

Реализация: свой PPO (`sb3_contrib`/RecurrentPPO в окружении нет), обучение по
последовательностям — минибатч = подмножество **сред** целиком по времени, чтобы
не рвать рекуррентность. GRU гоняется кусками между точками сброса памяти.

## Файлы

| файл | что делает |
|---|---|
| `meta_env.py` | RL²-обёртка над `MarsRoverVecEnv`: autoreset, `trial_start`, аугментация наблюдений, статистика по номеру эпизода в трайле |
| `train_rl2.py` | PPO + GRU, нормализация наблюдений (Welford), GAE, чекпоинты, jsonl-лог |
| `evaluate.py` | замер адаптации: награда/прогресс/успех по номеру эпизода; `--biome-split 2` — обобщение на **невиданные** биомы |
| `runs/<name>/` | `ckpt.pt` + `log.jsonl` |
| `logs/` | stdout прогонов |

## Запуск

```bash
.venv/bin/python claude/train_rl2.py --steps 120000000 --num-envs 256 --rollout 128 --run rl2
.venv/bin/python claude/evaluate.py --ckpt claude/runs/rl2/ckpt.pt --biome-split 1
.venv/bin/python claude/evaluate.py --ckpt claude/runs/rl2/ckpt.pt --biome-split 2   # test-биомы
```

Скорость на этой машине (RTX 5060 Ti, 20 CPU): ~144k env-steps/s при 256 средах.

## Метрики

Главное — не абсолютная награда, а **`adaptation_gain`**: прирост прогресса от
эпизода 1 к эпизоду 4 внутри трайла. Он положителен только если агент реально
использует память о задаче, а не просто выучил среднюю политику.
`succ_by_ep` — доля доездов до `finish_x = 800`.
