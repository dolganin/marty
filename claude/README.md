# RL² для Mars Rover (среда v12 — бюджет времени, энергия как связывающий ресурс)

## Что за задача на самом деле

Разбор среды (`environment/cpp/src/env.cpp`, `physics.cpp`,
`kEnvironmentVersion = "mars-env-v12-thermal-heater-launch-terrain"`):

* Трайл = **120 секунд = 7200 шагов** (`trial_time_limit`, dt = 1/60). Таймер
  тикает непрерывно и **не сбрасывается при гибели ровера**.
* `episodes_per_trial = 0`, `max_steps = 0` — **попыток внутри трайла не
  ограничено**. Переворот, застревание, разряд просто перезапускают ровер с x = 0
  **в том же мире** (`trial_mechanic_seed_` сохраняется), пока не кончится бюджет.
* Новый мир выдаётся только по `trial_exhausted()` -> `truncated`, следующий
  reset идёт с `trial_start = True`.
* Биом, цепочка из 14 зон, механики (Sand/Ice/Mud/Wind/LowGravity/Crust/Liquid),
  сид рельефа постоянны внутри трайла и **не наблюдаемы напрямую**. Рельеф виден
  только при активном лидаре, а лидар стоит энергии и имеет кулдаун.
* В v12 энергия стала связывающим ресурсом: батарея 75 (старт 60), но расход на
  тягу вырос в ~16 раз (`physics.cpp`, `0.00012 -> 0.0020`). Проехать далеко на
  стартовом заряде нельзя — нужно либо экономить, либо разворачивать панель.
  Контакт колеса с грунтом стал мягче и с ограничением силы.

Раз попыток бесконечно, а цена ошибки — **только потраченные секунды**,
оптимальная стратегия не «выжить», а **максимизировать метры в секунду**: быстро
опознать мир и ехать агрессивно, а не осторожно ползти.

## Решение: RL² (recurrent meta-RL)

Политика — GRU. Скрытое состояние **переносится через гибель ровера и все
попытки** и обнуляется только на `trial_start`. Наблюдение расширено:

`[obs, one-hot(prev_action), prev_reward, done, time_left_frac,
one-hot(attempt), best_x_in_trial]`

PPO максимизирует сумму наград за трайл (награда = пройденные метры минус
энергия минус штрафы), поэтому градиент сам выучивает: дешёвая разведка в первых
попытках → эксплуатация выведенного «типа мира» в остатке времени. Адаптация
происходит forward pass'ом GRU, без градиентных шагов на тесте (в отличие от
MAML) — то есть мгновенно.

`time_left_frac` в наблюдении обязателен: без него агент не знает, стоит ли
рисковать остатком бюджета. `best_x_in_trial` и номер попытки дают явный якорь
для памяти.

Реализация: свой PPO (`sb3_contrib` в окружении нет), минибатч = подмножество
**сред** целиком по времени, чтобы не рвать рекуррентность; GRU гоняется кусками
между точками сброса памяти.

## Оценка: несколько трасс, train и test

`evaluate.py` прогоняет политику на **нескольких трассах (сидах)** и усредняет:
`--train-seeds 101,202,303` (биомы из train-сплита) и `--test-seeds 1001,2002,3003`
(**невиданные** биомы, `biome_split = 2`). Для каждой метрики считается среднее и
std между трассами. Тот же eval вызывается из обучения каждые `--eval-every`
апдейтов и стримится в MLflow.

## MLflow

Всё пишется в MLflow: параметры запуска, метрики обучения, периодический
train/test eval и веса как артефакты.

```bash
# трекинг: sqlite + локальные артефакты (file store в MLflow 3.x отключён)
.venv/bin/mlflow ui --backend-store-uri sqlite:///claude/mlflow.db --port 5000
```

Логируется: `train/trial_best_m`, `train/trial_sum_m`, `train/attempts`,
`train/prog_attempt_*`, `eval_{train,test}/best_run_m` (+ std между трассами),
`total_distance_m`, `finish_rate`, `adaptation_gain_mps`, артефакт `weights/ckpt.pt`.

## Файлы

| файл | что делает |
|---|---|
| `meta_env.py` | RL²-обёртка: autoreset, детект конца трайла по бюджету, аугментация наблюдений, статистика по попыткам и трайлам |
| `train_rl2.py` | PPO + GRU, Welford-нормализация, GAE, MLflow, периодический multi-seed eval, чекпоинты |
| `evaluate.py` | оценка на нескольких трассах отдельно для train и test, усреднение |
| `runs/<name>/` | `ckpt.pt` + `log.jsonl` |
| `mlflow.db`, `mlartifacts/` | трекинг-стор MLflow |
| `runs/rl2_v10_old/`, `runs/rl2_v11/` | прогоны на прошлых версиях среды, для истории |

## Запуск

```bash
.venv/bin/python claude/train_rl2.py --steps 500000000 --num-envs 1024 \
    --rollout 128 --minibatches 8 --eval-every 250 --run rl2_v12
.venv/bin/python claude/evaluate.py --ckpt claude/runs/rl2_v12/ckpt.pt --trials 64
```

Производительность: `step_batch` распараллелен OpenMP только при `n >= 64`,
поэтому число сред большое — на 1024 средах ~200k env-steps/s.

## Метрики

* `best_run_m` — **как далеко ровер уехал за 120 секунд**, метров из 800.
  Прямой ответ на вопрос задачи.
* `total_distance_m` — суммарно пройдено за трайл по всем попыткам.
* `attempts_per_trial` — сколько попыток уместилось в бюджет.
* `speed_mps_by_attempt` — м/с по номеру попытки; рост = адаптация внутри трайла
  (прогресс последней попытки занижен обрывом по концу бюджета, поэтому мера
  адаптации именно скоростная).
* `finish_rate` — доля доездов до `finish_x = 800`.
