# RL² для Mars Rover (среда v11 — бюджет времени на трайл)

## Что за задача на самом деле

Разбор среды (`environment/cpp/src/env.cpp`, `include/mars/env.hpp`,
`kEnvironmentVersion = "mars-env-v11-trial-time-budget"`):

* Трайл = **120 секунд = 7200 шагов** (`trial_time_limit`, dt = 1/60). Таймер
  тикает непрерывно и **не сбрасывается при гибели ровера**.
* `episodes_per_trial = 0`, `max_steps = 0` — попыток внутри трайла сколько
  угодно. Переворот, застревание, разряд просто перезапускают ровер с x = 0
  **в том же мире**: `trial_mechanic_seed_` сохраняется, пока бюджет не исчерпан.
* Новый мир выдаётся только когда `trial_exhausted()` -> `truncated`, и следующий
  reset идёт с `trial_start = True`.
* Биом, цепочка из 14 зон, механики (Sand/Ice/Mud/Wind/LowGravity/Crust/Liquid),
  сид рельефа — постоянны внутри трайла и **не наблюдаемы напрямую**. Рельеф
  виден только при активном лидаре, а лидар стоит энергии и имеет кулдаун.

Итого: скрытая задача постоянна внутри трайла, а **цена ошибки — потраченные
секунды общего бюджета**. Оптимум — не «выжить любой ценой», а как можно быстрее
понять, в каком ты мире, и потратить остаток бюджета на дальний заезд.

## Решение: RL² (recurrent meta-RL)

Политика — GRU. Скрытое состояние **переносится через гибель ровера и границы
попыток** и обнуляется только на `trial_start`. Наблюдение расширено:

`[obs, one-hot(prev_action), prev_reward, done, time_left_frac,
one-hot(attempt), best_x_in_trial]`

PPO максимизирует сумму наград за трайл, поэтому градиент сам выучивает:
дешёвая разведка в первых попытках (включить лидар, попробовать газ, понять
сцепление/ветер/гравитацию) → эксплуатация выведенного «типа мира» в остатке
времени. Адаптация — forward pass GRU, без градиентных шагов на тесте
(в отличие от MAML), т.е. «мгновенная».

`time_left_frac` в наблюдении обязателен: без него агент не знает, стоит ли
рисковать. `best_x_in_trial` и номер попытки дают явный якорь для памяти.

Реализация: свой PPO (`sb3_contrib` в окружении нет), минибатч = подмножество
**сред** целиком по времени, чтобы не рвать рекуррентность; GRU гоняется
кусками между точками сброса памяти.

## Файлы

| файл | что делает |
|---|---|
| `meta_env.py` | RL²-обёртка: autoreset, детект конца трайла по бюджету, аугментация наблюдений, статистика по попыткам и трайлам |
| `train_rl2.py` | PPO + GRU, Welford-нормализация наблюдений, GAE, чекпоинты, jsonl-лог |
| `evaluate.py` | замер адаптации по номеру попытки + метрики трайла; `--biome-split 2` — невиданные биомы |
| `runs/<name>/` | `ckpt.pt` + `log.jsonl` |
| `runs/rl2_v10_old/` | прогон на старой версии среды (4 эпизода на трайл), для истории |

## Запуск

```bash
.venv/bin/python claude/train_rl2.py --steps 400000000 --num-envs 1024 \
    --rollout 128 --minibatches 8 --run rl2_v11
.venv/bin/python claude/evaluate.py --ckpt claude/runs/rl2_v11/ckpt.pt --biome-split 1
.venv/bin/python claude/evaluate.py --ckpt claude/runs/rl2_v11/ckpt.pt --biome-split 2
```

Важно про производительность: `step_batch` распараллелен OpenMP только при
`n >= 64` и на новой физике двигателя стоит дорого. Замеры: 64 среды — 5k sps,
256 — 21k, **1024 — 93k**. Поэтому число сред большое.

## Метрики

* `trial_best_m` — лучший заезд за 120 секунд, в метрах (из 800). Это прямой
  ответ на «как далеко проезжает».
* `trial_sum_m` — суммарно пройдено за трайл по всем попыткам.
* `prog_by_attempt` — прогресс по номеру попытки внутри трайла. **Рост слева
  направо = агент действительно адаптируется к скрытому миру**, а не просто
  выучил усреднённую политику.
* `attempts` — сколько попыток уместилось в бюджет.
